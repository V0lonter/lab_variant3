## Як влаштована програма

- `main()` створює **один** об'єкт вхідних даних `std::shared_ptr<const InputData>` (таблиця вузлів і точка `x0`) і передає його обом алгоритмам.
- Кожен алгоритм повертає результат як `std::unique_ptr<Result>`.
- Поля результату (`method`, `value`, `error_estimate`, `operations`, `time_us`) розпаковуються через structured bindings.
- Ручного керування пам'яттю (`new`/`delete`) немає.

## Збірка та запуск

```bash
cmake -S . -B build
cmake --build build
./build/Lab1App            # Windows: build\Debug\Lab1App.exe
```

У Visual Studio 2022: **File → Open → Folder**, вибрати `Lab1App.exe` як стартовий елемент і натиснути Ctrl+F5.

## Що виводить програма

1. Таблицю результатів обох методів для `y = sin(x)` (8 вузлів на `[0, 3]`, `x0 = 1.1`): значення, оцінка й фактична похибка, кількість арифметичних операцій, час.
2. Порівняння методів.
3. Експеримент на функції Рунге `1/(1+25x²)`: залежність похибки та вартості від кількості вузлів.

| | Лагранж | Кубічний сплайн |
|---|---|---|
| `y(1.1)` для `sin(x)`, 8 вузлів | 0.89120877 | 0.89112387 |
| Фактична похибка | 1.41·10⁻⁶ | 8.35·10⁻⁵ |
| Операцій (n = 8) | 232 | 121 |
| Похибка для функції Рунге, n = 21 | 18.6 | 6.07·10⁻⁵ |
| Операцій, n = 81 | 26001 (O(n²)) | 1362 (O(n)) |

**Висновок.** На гладкій функції з малою кількістю вузлів поліном Лагранжа точніший. Зі зростанням `n` на функції Рунге він розходиться (ефект Рунге), а похибка сплайна монотонно зменшується. Для одного значення Лагранж має складність O(n²), сплайн — O(n).

## Обмеження

- Потрібно щонайменше 3 вузли, `x` строго зростають, `x0` лежить у межах таблиці (екстраполяція не підтримується); порушення дає `std::invalid_argument`.
- Оцінка похибки евристична: прибирається найближчий до `x0` внутрішній вузол і порівнюються результати (для сплайна різниця ділиться на 15). Тому додатково виводиться фактична похибка відносно точного значення.
- Час виміряно в одній конфігурації, на іншому комп'ютері й у Release числа будуть іншими.
